# CPS 合約轉未填：AI 作業指引候選046e

**狀態：供獨立語義審查及有界來源測試的開發候選，尚未通過部署。** 046e 沿用046d，並依所有者決定加入R45（有報價或位於盤內的列才是未填列；無箱體且無估價者列入普查不成列）、R46（無主項的單價分析只列普查）及R47（括號縮寫留在C）；路由新增普查角色 excluded_supply 與 analysis_unlinked。046d 沿用046c的介面、工具與規則R1–R24，另在 `FIELD_ROLES.md` 加入R25（單價分析組成列的單位、數量與專案層級欄位）、R26–R38（046c 待決問題的通用決定）及R39–R44（046c 開發批次1觀察到的通用錯誤類別）。046c 已在 `FIELD_ROLES.md` 加入通用分配規則R1–R12（財務註記與供應基礎限定詞、融合材料字、數量、D欄連接符、文件參照、當事人角色、縮寫、未決類別、真實空白原因、總計差異、非材料角色、規則優先）。供應基礎限定詞依所有者決定置於D；工作範圍數量及數量基準數量的C/D位置仍未決。本套件沒有已核准的模型測試成績。預定執行者是具備指定工具的 AI agent；實際模型、推理設定、套件雜湊與來源範圍須於每次執行記錄。不得把本文件的存在或機械檢查通過當成語義正確或部署核准。

## 目的與讀取順序

未填是供繪圖人員沿用格式修改成已填的供料清單。從當次獲准合約辨認材料與契約服務，產生17欄草稿；不得替設計、選型、採購或後續製造補資料。整案議價不是未填材料，也不是材料單價。

先讀本文件，再依序讀 `resources/SOURCE_READING.md`、`resources/FIELD_ROLES.md`、`resources/NAMING_RULES.md`、`resources/NAME_POLICY.json`、`resources/SOURCE_REFERENCE_CONTRACT.md`、`resources/OUTPUT_CONTRACT.md`、`resources/REVIEW_CHECKLIST.md`。`resources/SYNTHETIC_NAMING_CASES.json`、`resources/SYNTHETIC_ALLOCATION_CASES.json` 及 `resources/EXAMPLE_INVENTORY.json`/`resources/EXAMPLE_RESPONSE.json` 是人工編造的示例，只示範格式與政策，不能當成實際合約證據、預期答案或測試通過紀錄。兩份 JSON schema 與 `tools/cps046b_route.py` 共同定義回覆介面；檢查器只驗證結構與參照，不代表語義正確。

## 1. 確認來源與工作範圍

只讀當次清單內、雜湊相符的原始合約、已證明納入合約的原始附表及已核對的工程識別資料。確認提供者、確切檔案與版本、採用依據、完整性及各表角色。檔名、資料夾、時間戳、頁名、可見/隱藏狀態不能單獨證明有效契約版本。

禁止用歷史未填、已填/OK、後期內部電機圖、板金/鈑金圖、製造/採購文件、型錄、公司習慣、評分答案或前次模型結果填入生成值。客戶原始圖面可以在另一個有來源查證的調查工作檢視，但未因此獲准加入本合約限定生成流程。不得因工具能讀某檔案就視為來源授權。

遇明示引用卻未附的明細、附件採用不明、版本衝突、整表無法讀取或關鍵公式錯誤，列出具體缺件/衝突並停止完成受影響範圍。可保留有效局部草稿，但完整分母與未處理區域不能消失。不得用另一個可讀的預算、報價或分析頁自行補替。

## 2. 完整閱讀與建立來源清冊

逐表/逐頁讀完整來源，包括表頭、隱藏資訊、續行、備註、數量/金額欄的商務文字、單價分析、零值、小計、總計和頁尾。保持原檔只讀；不執行巨集、不更新連結、不重算、不修正來源。真空白、空字串、零、文字數字、數值、有效快取、缺少快取、錯誤與合併覆蓋格須分清。

先形成不可變的完整來源清冊與可讀視圖；不得只保存成功抽到的列。來源參照、原始型別、原始字串/快取及讀取限制都要保留。影像重排或換行只是檢視輔助，不能創造原始儲存格字元。掃描PDF的視覺讀取與文字辨認須標示不確定位置。

## 3. 確認表格角色與項目層次

以內容和採用證據區分契約明細、預算、報價、變更、總表、資源統計與單價分析，不把替代版本串接成重複材料。先接完整的標題及項目續行，再建立章節、項次、場所、盤體與子項關係。

有單位或數量不必然是材料；單位為「式」或數量空白也不必然是盤體。場所、契約章節、契約盤體群組與物理箱內歸屬分開記錄。只有明確的編號祖先/後代、完整標題與子項語境支持時才指派盤體關係；離開範圍就停止沿用。不能把最近一個盤名傳給所有後續項目。

每個契約需求只產生一次主項。契約服務、組裝、搬運、運費、安裝、測試與設計行保留其服務意義。稅額、整案議價、總價、頁碼、簽名及分析小計不產生材料。

單價分析的組成必須完整讀取，但它不是額外採購需求。只有主項代碼/名稱、單位與正數每單位基數有明確關聯時才建立組成連結；保留原數量與基數，不能乘上主項數量再當新購料。無法證明連結、是否展開或倍率時保持待查，不刪掉組成、不補數、不把同名當同一項。依R46，所引用項目不是本回覆需求項目的分析區塊不產生組成，整塊列為 analysis_unlinked。資源統計只作來源核對，不能替代需求明細。

## 4. 從完整項目辨認名稱

材料名稱可能在型號、極數、電壓或料碼之後，也可能只在規格欄或續行。讀完同一邏輯項目的描述、規格及有支持關係的備註後，辨認實際供應的物件/配件/組合/服務。不要以第一個詞、第一個逗號、固定欄位或短詞庫決定名稱。

依 `NAMING_RULES.md` 保留完整、具體的名詞及功能差異；數字不一律移出名稱，組成數量仍須緊連它修飾的物件。分清額定值、尺寸、材質、通訊介面、盤號、標準代碼、型號、品牌和商務註記。只因像型號不能填I；知道型號的常見廠牌也不能從記憶填J。

C/D/I/J採用原合約文字及局部語境證據。名稱清楚而前置碼角色不明時，可以抽出有證據的名稱，保留碼與待查原因而不捏造型號。原文只有縮寫就保留縮寫；原文為中文就保留中文，不為了像歷史未填而翻譯或改寫。公司顯示別名必須有另外核准的版本化政策；本候選沒有核准別名。

## 5. 完成17欄並保存每個決策

依序：A盤體名稱、B盤體規格、C材料名稱、D規格、E單位、F數量、G單價、H複價、I型號、J廠牌、K訂購廠商、L工程編號、M訂購客戶、N使用客戶、O需要日期、P需要數量、Q合約價。詳細角色見 `FIELD_ROLES.md`。

每個非空值都有來源與轉換證據；每個空值有具體原因，區分來源未載、角色未證明、無法辨讀、階段應留白與尚未處理。未知不是成功抽取。保留全項原文與角色分配，不能從整理後的輸出反造證據。

價格和數量不靠名稱推算。G/H保持此階段的採購價空白。Q只有已確認採用的該材料契約單價可填。缺價不等於零、不等於不負責；「沒有箱體且沒有估價」必須兩條件均成立才支持該責任判斷；依所有者決定（R45），兩條件確實成立的需求列不列入未填，其儲存格以 excluded_supply 留在普查中；盤內列、R42保留列及價格或盤體關係有疑義的列一律保留（R45）。供料、自運、不含估價及責任排除各自保留，不任意刪除項目。需要數量P不能自動抄F，交貨條款不能自動當O。

## 6. 檢查殘留意義與完整覆蓋

檢查每個名稱、具體名詞、組合成分、型號候選、技術條件、數量修飾、配件、服務及商務資訊都有目的欄或明確待查記錄。不能把配件變主設備、服務變材料、接地系統變成單顆器材。重新核對項目邊界、組成連結與全表去向。

來源清冊的每一位置必須在覆蓋帳中存在。被材料使用的項次仍有項次/清冊角色；不能因為用作錨點就從應保留的非材料清冊消失。機械補齊未分類的格子只證明資料被保留，不能把它們改稱已判讀。

## 7. 凍結、組裝與發布狀態

返回符合 `SEMANTIC_RESPONSE.schema.json`（`cps.semantic-source-refs.v2`）的語義決策與來源參照，回覆前以 `python3 -I tools/cps046b_route.py check --inventory SOURCE_INVENTORY.json --response 回覆.json` 自我檢查。`invalid` 須依來源更正；`unrepresentable_hold` 表示既有寫表器無法承載真實答案（例如以 -、=、+、@ 開頭的值或待查組成連結），保留原值並說明，不得為通過檢查而改值。來源複製工具只能驗證參照並按固定表示規則取值；不能代選名稱、修補判斷或套用評分答案。只讀當次提供的來源封包與本套件，不搜尋其他檔案。

凍結原始回覆、決策、來源清冊、套件及執行設定後，才以另外角色評估。歷史未填不得進入生成上下文。寫表器按已凍結的17欄值製作草稿；須做完整儲存值核對與可讀性檢視，不能把寫檔成功當成內容正確。

完成 `REVIEW_CHECKLIST.md` 後仍只能標示符合實際證據的 research_draft、partial 或 held。本候選不授權正式供料、採購或無人審查部署。可靠性需要整套指引/資源/模型/工具的獨立來源核對及保留集測試，不能由少量示例、兩讀者一致或格式檢查取代。
