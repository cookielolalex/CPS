## Route

0. **Node environment (v2.3, review S1; v2.4, second review N-c).** Every node process the writer starts runs with an allowlisted environment: only `PATH`, `HOME`, `TMPDIR`, `LANG` and `LC_*` are passed (`NODE_ENV_KEEP`). So no `NODE_*` variable (`NODE_OPTIONS`, `NODE_PATH`, `NODE_EXTRA_CA_CERTS`, …) and no `OPENSSL_CONF`, `LD_PRELOAD`, `LD_LIBRARY_PATH` or other variable reaches node: no `--import`, `--require` or loader hook from the environment, no global module path, and no OpenSSL provider loaded from a configuration file. The allowlist does not make the node binary safe (third review G2): the writer runs whatever `--node` names, or whatever `PATH` finds for a bare name, and an absolute path to a wrapper script is just as unsafe as a `PATH` entry, because the wrapper can start the real node with `--import` or any other flag. v2.5 resolves the executable once, records its realpath and sha256 in the receipt (`node_environment.node`), and runs that realpath for every node process, so the record names the file that ran (`NODE_UNAVAILABLE` if nothing is found); the writer does not enforce them, and a wrapper is recorded as itself. Only saved QA run with `--checker-node` and `--checker-node-sha256` pins the node, for the checker ("Conditions of use"). `LD_PRELOAD` and `LD_LIBRARY_PATH` in the caller's environment still affect Python itself, which is outside this check. The allowlist is for POSIX systems (on Windows node needs further variables such as `SystemRoot`; not supported or tested). The writer directory is used by its real path, and each pinned writer file must be a regular file in it (`WRITER_FILE_OUTSIDE_WRITER_DIR`): node resolves imports from a module's real path, so a symlinked `validate_carrier_v4.mjs` would load `writer004.mjs` and `@oai/artifact-tool` from elsewhere. Before any other node run, `@oai/artifact-tool` is resolved the way node resolves it from `writer004.mjs`: `createRequire(<writer004.mjs URL>).resolve('@oai/artifact-tool')`, and also `import.meta.resolve` from the writer directory (writer004 imports it as ESM); the two must name the same file (`ARTIFACT_TOOL_RESOLUTION_DIVERGES`, for example conditional `exports`). The file must have the stub's sha256 `67134acad4326089bca7cd074c753bda88887a64c6a1499d15e1153d673796a4` (`ARTIFACT_TOOL_NOT_PINNED`) and its `package.json` the documented content (`ARTIFACT_TOOL_PACKAGE_UNEXPECTED`); an unresolvable specifier is `ARTIFACT_TOOL_UNRESOLVED`. The receipt's `node_environment` records the kept and the removed variable names (`kept_variables`, `removed_variables`; names only, never values), the node executable with its realpath, sha256 and version, and the resolved stub path and sha256.
1. **Gate.** The writer runs the archived `validate_carrier_v4.mjs` in node, unchanged and with the `@oai/artifact-tool` import resolved to the CPS validation stub. It refuses unless the result is `WRITER_STRUCTURAL_VALIDATION_ONLY` for the same carrier sha256. The writer files are pinned by sha256:
   - `writer004.mjs`: either `85a7f619…c0d7` (the archived original) or `70d7f664…efb7` (the public copy in `research/checkpoint045/writer/`). The two differ only in the redacted Windows helper path on line 218, which validateCarrier/prepareMatrices never reach.
   - `validate_carrier_v4.mjs`: `984da083…e013`.
   - `receipt_bytes.mjs`: `b2ff15fd…1d2c`.
2. **Matrices.** A Python reimplementation of writer004 `prepareMatrices`, including its review-cell check (`REVIEW_CELL_UNSAFE_OR_TOO_LONG`). `validate_carrier_v4.mjs` does not run that check. The reimplementation uses JavaScript semantics:
   - all JSON numbers are binary64;
   - `JSON.stringify` quoting, including escaped lone surrogates;
   - ECMAScript `Number::toString`;
   - property order with array-index keys first.

   The route tool's Python port (`cps046b_route.py`) validates only and builds no matrices, so it is not reused. The tests check that the shared constants match it.
3. **Cross-check (every run).** writer004's own `prepareMatrices` runs on the same carrier through `writer004_matrices.mjs`. Its `JSON.stringify({sheets}, null, 2) + "\n"` must be byte-identical to the Python text, or the carrier is refused (`CROSS_CHECK_MISMATCH`). Each saved `EXPECTED_SAVED_VALUES.json` is therefore the exact text writer004 would have written for that carrier.
4. **Writability.** The writer refuses cell text that the openpyxl/XML route cannot carry unambiguously. See "Extra refusals" below.
5. **Assembly.** openpyxl writes the workbook from the matrices. Strings stay strings, numbers stay numbers, empty stays empty, and no formula is ever written. Output bytes are reproducible: the same carrier and job title give the same xlsx sha256.
6. **Naming (v2.6, O33).** With `--job-title`, the workbook file is `<name>.xlsx` and the main sheet `<name>`, derived from the title as described in "Owner decisions O33–O34 (v2.6)". The matrices, the cross-check and `EXPECTED_SAVED_VALUES.json` keep writer004's sheet name `未填研究草稿`. The receipt's `deliverable.sheet_mapping` maps each `EXPECTED_SAVED_VALUES.json` sheet to its workbook sheet. Without `--job-title` the names are the v2.5 ones.

## Mode v2: route v4.1 relaxations for 046f carriers (route v4.2)

`--mode v2` is for carriers made by route v4.2 (`research/guideline046_006/package/tools/cps046b_route.py`, `cps046f-route.v4.2`), which keeps the route v4.1 relaxations unchanged and adds only response checks (R48/R56 policy checks). The route's convert receipt says when it is needed (`export_mode_required`, with one entry per relaxation class).

The route's Python writer port `validate_carrier_port` is writer004's validateCarrier plus the prepareMatrices review-cell check, with the relaxations listed in its `PORT_RELAXATIONS`; `validate_carrier_port(c, strict=True)` applies none of them. The route tests show by parity fuzzing that the strict port equals node writer004 on every fuzz carrier, and that every divergence of the relaxed port falls in one of the classes below.

| Class | Carrier feature | writer004 check | Neutralization in the placeholder copy |
|---|---|---|---|
| `o13_m_n_selection_evidence` | an evidence object for column M or N that holds `selection_evidence` (O13, R48) | `SELECTION_ONLY_ENGINEERING_ID` | The object loses `selection_evidence` and gains `location` = the item's own `location`, `anchor` = the item's `anchor` and `raw_text` = the `selection_evidence` text. `transformation` and any other key are unchanged, so a malformed object stays malformed. |

A non-list `review_reasons` is left unchanged, so writer004 still refuses it. Values, raw, evidence and `null_reasons` are unchanged, so the null reason for C is still required. |
| `o16_q_unverified_adoption` | a non-null Q while `metadata.source_adoption` is not `verified` (R54, O16) | none: writer004 never reads the adoption status | None. Q and the metadata stay unchanged, in the copy and on the v1 route. |

Nothing else in the carrier changes in the copy: groups, nonitems, metadata, limitations and every other item are copied unchanged.

- **Carrier without the first two classes** (including a carrier whose only relaxation is O16): exactly the v1 route above. The output bytes equal mode v1. The receipt still lists the O16 items.
- **Carrier with an O13 or R57 class:**
  1. **Placeholder copy** as in the table. The copy has the shape writer004 requires, and the item's own location is valid by construction.
  2. **Gate (both must pass).** writer004 `validate_carrier_v4.mjs` runs unchanged on the copy (stage `gate:validate_carrier_v4:placeholder_copy`).   3. **Cross-check.** writer004 `prepareMatrices` runs on the copy and must be byte-identical to the Python matrices of the copy (stage `cross_check:placeholder_copy`).
  4. **Allowed difference.** The Python matrices of the original carrier, which are saved, may differ from the copy's matrices only in these review-sheet cells. The rows of both matrices are aligned from writer004's review-row layout of each carrier, so every row is accounted for:
     - O13: columns C–E (evidence location, anchor and JSON text) of each `欄位依據 <id>.M` or `<id>.N` row of a field with selection evidence. The original has writer004's own selection-evidence form there: an empty location, the anchor `"已核對工程選取"` and the JSON of the selection evidence. That is the code path writer004 uses for L.
     - R57: column G (`狀態`) of every review row of the item (`research_draft` in the original, `held` in the copy).
     - R57 with an added placeholder reason: column F of the item's `項目` row (`[]` in the original), and the copy's one extra `待確認 <id>.1` row holding the placeholder reason, which the saved matrices do not have.
     Main, component and link sheets must be identical. Any other difference refuses the carrier (`RELAXATION_DIFF_OUTSIDE_DOCUMENTED_CELLS`); a relaxed cell or added row without the documented form refuses it too (`RELAXATION_DIFF_FORM`).
  5. **Receipt.** `WRITER_RECEIPT.json` records `mode` and a `relaxations` section: the three classes with their fields or items and their neutralization text, the placeholder-copy sha256, the route port path, sha256 and version, the copy cross-check, every differing cell (saved-matrix coordinates) and the rows added in the copy. It also adds an extra limitation. `expected_saved_values.identical_to_writer004_prepareMatrices_output` is `false`, with `identical_to_writer004_prepareMatrices_on_placeholder_copy_except_documented_cells: true`.
- **Refusals in mode v2.** Selection evidence on any column other than L, M or N is still refused by writer004 on the copy (`SELECTION_ONLY_ENGINEERING_ID`). Path-like or malformed M/N selection evidence is refused by writer004 on the copy or by the route port. A null C without a nonblank null reason, a non-list `review_reasons` and any other status are refused by writer004 on the copy. Every other writer004 refusal is unchanged.

How each one works:

- **G2, node binary.** The writer resolves `--node` once (a path as given, a bare name in the allowlisted `PATH`), hashes the realpath, records `command`, `executable`, `realpath`, `sha256` and `version` in `node_environment.node`, and runs that realpath for every node process. In saved QA, `--checker-node` must be an absolute path and comes with `--checker-node-sha256` (64 hex digits); it excludes `--node` and needs `--carrier`/`--writer-dir` (usage errors otherwise). The realpath's sha256 is compared with the pin before any node call; a mismatch or an unreadable file is `CHECKER_NODE_REFUSED`, and then no node call and no rerun is made. Every node call then runs the realpath: the `@oai/artifact-tool` resolution and `writer004_matrices.mjs` of the writer004 check, and the writer rerun, which gets it as `--node <realpath>`. The rerun receipt must name the same realpath and sha256 (a `provenance` finding otherwise), and the file is hashed again after the last node call (`sha256_after_check`). `expected_provenance` records `checker_node`, `writer004_check_node` (v1 receipts) and `rerun_node`. The producer receipt's own node record is shown as `receipt_node`, with `receipt_node_matches_checker_node`, and is never used or compared: the checker reruns everything with its own node, so the producer's node is not evidence. Without `--checker-node` (`--node`, default `node` from `PATH`) saved QA still runs, records which binary ran, and reports `pinned_checker_node` false. A wrapper is then visible in `checker_node`, `writer004_check_node` and `rerun_node`, but the run is not CPS evidence.
- **G3, receipt claims.** The rerun always uses `--mode v2`. For a receipt that says v1, the expected `mode` is `v1` and the expected `relaxations` is `{"applied": false, "scanned": false}`. That is exactly what a v1 run writes for a carrier without O13/R57: the v1 route is the v2 route without O13/R57, and test `h_v1_receipt_claims_equal_v2_except_mode_and_relaxations` checks that every other compared field is the same in the v1 and v2 receipts. A rerun that applied relaxations keeps `mode` v2, so a v1 claim on a relaxed output mismatches. Values are compared as canonical JSON, so `0` is not `false`. The only path in `relaxations` is `route_v4_port.path`, the route tool's location on the writer's machine; it is left out, and the tool's sha256, version and result are compared. `writer_files` is compared whole (sha256 and identity), so the checker's `--writer-dir` must hold the same writer004 pin as the producer's. `writer` is compared, so an output of writer v2.4 fails saved QA v4 on `writer`.
- **G1, pinned parts.** Checked first: the 8 parts have the same bytes in all 65 untampered outputs of the third review's runs (both writer directories, the fidelity probe and the reviewer's wrapper outputs) and in every writer output of this suite (test `g_pinned_parts_constant_in_every_output`). `docProps/core.xml` holds created and modified `1980-01-01T00:00:00Z`. The writer sets `wb.properties.created`/`modified` to `FIXED_TIME` and serialises with `ExcelWriter.save()` directly, which skips openpyxl's `save_workbook` (that would set `modified` to now; L8). `docProps/app.xml` holds `Openpyxl 3.1.5`, so saved QA now passes only outputs written with openpyxl 3.1.5. Every zip entry with a pinned name is hashed, including duplicate entries. With `workbook.xml` and `styles.xml` pinned, any style or workbook change fails, including colour tints and fonts in another namespace.
- **G1, namespace.** Every element of every worksheet must be in the transitional SpreadsheetML main namespace (finding `element_namespace`). The structure checks compare exact names: `tag_name` gives the local name only for that namespace, and the full tag otherwise (`{}name` for an element with `xmlns=""`). So a Strict `<v>` is also an unexpected cell child. Attribute allow-lists already compared exact keys.

Results: B01–B06 fail saved QA without provenance: B01–B03 with `element_namespace` (plus `worksheet_structure`), B04–B06 with `pinned_part` (B06 also `font_structure`). ### O33: deliverable naming

`--job-title "<project folder title>"` is a per-job input, like the job inputs behind L/M/N under O13. The harness supplies it; the generator never does. The writer derives `<name>` from it (`deliverable_record`):

1. NFKC-normalize the title, then remove every whitespace character (`str.isspace()`, plus U+FEFF). NFKC turns full-width digits, letters, parentheses, hyphens and commas into ASCII, and U+3000 and U+00A0 into spaces, which are then removed.
2. The result must start with a 7-digit ASCII case id. Remove the first `-` among the 6 characters after it (positions 8–13), and no other. A `-` directly after the case id counts as the first of those characters, so it is removed too. Only the ASCII hyphen-minus counts. NFKC maps `－` (U+FF0D) to it; `‐` and `–` stay as they are.
3. Append `(未填)`.

From `<name>`:

- **File:** `<name>.xlsx`, with `\ / : * ? " < > |` replaced by `-`.
- **Main sheet:** `<name>`, with `: \ / ? * [ ]` replaced by `-`. The text before `(未填)` is cut, whole code points only, so that the sheet name has at most 31 UTF-16 code units and always ends in `(未填)`. An astral character counts as 2 units.

The writer refuses the title (`JOB_TITLE_INVALID`, stage `usage`, nothing created; `detail.reason` names the case) when:

- it has no case id (`CASE_ID_REQUIRED`, including an empty title);
- a control, surrogate, U+FFFE or U+FFFF character remains (`UNREPRESENTABLE_CHARACTER`);
- the sheet name holds a literal `_xHHHH_` (`LITERAL_OOXML_ESCAPE_SEQUENCE`, as for cell text);
- the file name exceeds 255 UTF-8 bytes, one path component on Linux (`FILE_NAME_TOO_LONG`).

Because the name starts with 7 digits and ends in `(未填)`, it can never begin or end with an apostrophe, be a reserved Windows device name, or equal another sheet's name.

### Extra refusals (the portable writer refuses carriers writer004 might accept)

- **Non-UTF-8 carrier bytes** (`UTF8_REQUIRED`). Node decodes them with U+FFFD and accepts.
- **A written cell string containing a lone surrogate, U+FFFE or U+FFFF** (`PORTABLE_UNREPRESENTABLE` / `XML_UNREPRESENTABLE_CHARACTER`). XML 1.0 cannot carry these. A lone surrogate that occurs only inside a JSON-encoded review cell is escaped by `JSON.stringify` and is written normally.
- **A literal OOXML escape sequence `_xHHHH_` in written text** (`LITERAL_OOXML_ESCAPE_SEQUENCE`). Spreadsheet applications decode it: LibreOffice reads an openpyxl-written `_x0041_` as `A` (measured), and openpyxl writes it unescaped. Escaping it as `_x005F_x0041_` would also make openpyxl readback differ from the value, so the route refuses. Partial patterns such as `AB_x12_` or `_x004` are fine.
- **Any difference between the Python and node matrices** (`CROSS_CHECK_MISMATCH`).
- **A node environment other than the pinned one** (stage `gate:node_environment` or `gate`): `ARTIFACT_TOOL_UNRESOLVED`, `ARTIFACT_TOOL_RESOLUTION_DIVERGES`, `ARTIFACT_TOOL_NOT_PINNED`, `ARTIFACT_TOOL_PACKAGE_UNEXPECTED`, `WRITER_FILE_OUTSIDE_WRITER_DIR`, `NODE_UNAVAILABLE`. writer004 itself would run with whatever node resolves.
- **Job title (v2.6):** a `--job-title` from which no deliverable name can be derived (`JOB_TITLE_INVALID`, stage `usage`; see "Owner decisions O33–O34 (v2.6)"). This refuses an input, not a carrier.
- **Mode v2:** any difference between the saved matrices and writer004's matrices of the placeholder copy outside the documented cells (`RELAXATION_DIFF_OUTSIDE_DOCUMENTED_CELLS`, `RELAXATION_DIFF_FORM`), any refusal by the route v4.2 port, a route tool whose bytes are not the pinned ones (`ROUTE_V4_TOOL_NOT_PINNED`, checked before it runs), and a pinned route tool whose `VERSION` or `PORT_RELAXATIONS` keys differ (`ROUTE_V4_TOOL_VERSION`, `ROUTE_V4_TOOL_RELAXATIONS`).

### QA notes (review N2)

- **Never re-save the workbook with LibreOffice (or Excel, or any application) for QA.** Saved QA and visual QA run on the writer's bytes. A re-saved file is another workbook (string storage, number text, styles and types can change); its QA says nothing about the writer output. `visual_qa.py` renders a temporary copy and checks that the saved file is unchanged.
- **Subnormal numbers may flush to zero in Excel.** The workbook stores subnormal doubles such as 5e-324 exactly, and saved QA proves the stored text and value, but Excel may treat subnormals as 0 when it reads, displays or calculates them. The stored value is what CPS saved QA establishes.
